# M4 — 真机 e2e 验收工具包与清单

> 本节是给测试者的操作卡：在开发机（联网）准备产物，到安静房间按清单执行。

## 准备（联网机）

1. `dist/airqr-linux-amd64`（或 Windows 上直接 `airqr.exe render` + 播放器）→ 拷到测试机。
2. `dist/airqr-v1.0.apk` → 侧载到安卓手机（Android 10+）。
3. 测试样本：`python -c "import os;open('t100k.bin','wb').write(os.urandom(102400))"`，
   同法做 1MB / 10MB 样本。记录各自 sha256。

## 验收矩阵（每格 = 一次完整传输 + sha256 比对）

| # | 样本 | 屏幕档位 | 距离 | 光线 | 通过标准 |
|---|---|---|---|---|---|
| 1 | 100KB | grid4/v40/L/4K | 40cm | 暗 | ≤30s, sha 一致 |
| 2 | 1MB | grid4/v40/L/4K | 40cm | 暗 | ≤90s, sha 一致 |
| 3 | 1MB | grid4/v40/L/4K | 40cm | 亮(白天) | ≤120s, sha 一致 |
| 4 | 10MB | grid4/v40/L/4K | 40cm | 暗 | ≤10min, sha 一致 |
| 5 | 1MB | grid2/v25/L/1080p | 40cm | 暗 | ≤3min, sha 一致 |
| 6 | 1MB | grid6/v40/L/4K | 40cm | 暗 | ≤60s, sha 一致 |
| 7 | 1MB | grid4, 中途离手 10s 再续 | 40cm | 暗 | 最终 sha 一致 |
| 8 | 1MB | grid4, 斜 15° | 40cm | 暗 | sha 一致 |
| 9 | 1MB | grid4/v40/L/4K，**横持手机**（预览应自动转正，诊断行带 L） | 40cm | 暗 | sha 一致，码占幅明显大于竖持 |
| 10 | 1MB | grid4/v40/L/4K，竖持（诊断行带 P） | 40cm | 暗 | sha 一致 |

判定：10 项中 ≥8 项通过 = M4 验收 PASS；第 4/7 项为必过项。第 9/10 项对比横竖持耗时。

## 记录

每项记录：实际秒数、是否一次通过、失败时现象（解码慢/进度停滞/不识别）。
把数据填进 bench/report.md（M4 完成后归档）。

## 工具

- 手机端进度页已显示「solved/K 块」与文件名。
- 发送端 `send` 显示 pass 计数；测试中途不可暂停播放（除非测试项要求）。
- 若端到端吞吐显著低于预期（<50% 预算值），先用 `bench/py/matrix.py` 离屏复测
  分辨率/网格档位，再检查环境光与帧率设置。
